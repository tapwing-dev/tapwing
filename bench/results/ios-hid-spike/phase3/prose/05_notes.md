Measured. Pure Flutter flows do not spawn `xcodebuild` with the flag on (0 of 3 in both flows). `f2_endless_animation` shows no HID event and no timing change. `f7_app_health` opens the HID backend (one `hid_open` of about 66 ms and two failed snapshots per run) because a lookup misses the 400 ms probe, and its median is 74 ms slower (3026 to 3100 ms). The ranges overlap (2996-3114 against 3069-3108) and there are only 3 runs per cell with no warm-up, so treat 74 ms as the order of magnitude. The 66 ms is the one-time cost of loading the private frameworks.

Fallback (measured). All four forced failures pass through the runner, and in none of them was an input delivered twice. `open` switches HID off with one warning and the runner does the touch (1 runner touch, 0 HID touches). `snapshot` and `frame` fail one route, the runner starts, and the alert tap goes out once through the client HID route (1 HID touch, 0 runner touches). `touch` fails the surface touch before sending (the failed HID call is logged as `ok=0`, then `hid_fallback`), the runner starts, the client tries HID once more and fails again, and the runner delivers the one real tap. The app state ("Permission: granted") confirms a single answered alert in each run. The forced-touch failure fires before the shim sends anything, so these runs exercise the "nothing sent" fallback but not the "may have been sent" branch. That branch is covered only by unit tests.

Flag off (measured and read). The flag-off run has 0 `hid` or `hid_open` events. In code: `session_for` returns `None` when `TAPWING_IOS_HID` is not `1` (`hid/mod.rs`), so `set_hid(None)` and `ios_hid: None`. `hid_for_input` and `hid_active` return before they touch the device, `hid_split` is false, and `try_hid_surface` and `hid_focus` return `None`. The only unconditional change is that on macOS the shim is now compiled and linked into the binary (`build.rs`, new build dependency `cc`). Nothing in it runs without the flag.
